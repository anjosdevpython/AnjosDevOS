# Plan 01-05 — Auto-Patch + Real Test Execution

## Goal

Complete the **inner loop** of the IDE: from a finding, generate a patch, show a diff, accept/reject, write to the WebContainer VFS, run a real Vitest suite, and commit. Plus a basic `git` workflow that uses the WebContainer's built-in git.

## Context

- **What exists today:** `analyzeCodeQuality` returns a hardcoded `fixedCode` for the `eval` regex. The Code Editor has a Save button that doesn't actually save (writes to React state). No test runner. No git.
- **What this plan delivers:**
  1. `PatchApplier` component: Monaco `DiffEditor` for the proposed change, accept/reject/undo.
  2. The Save button now writes to the WebContainer VFS.
  3. `Vitest runner` that spawns `npx vitest run` in the WebContainer, parses JSON output, streams pass/fail cards to the SwarmPanel.
  4. `git` workflow: on workspace creation, `git init`; on save, `git add`; explicit "Commit" button.
- **Why now:** with the LLM audit (Plan 1.4), we have findings with `fixedCode`; the WebContainer runtime (Plan 1.2) gives us a place to write and run; this plan wires the inner loop end-to-end.

## Tasks

### Task 1.5.1 — Create `src/lib/runtime/patchApplier.ts`

- Functions:
  - `proposePatch({ path, currentCode, fixedCode }): { diff: string, hunks: DiffHunk[] }` — computes a unified diff (use `diff` npm package or hand-roll a simple LCS).
  - `applyPatch({ workspaceId, path, newCode }): Promise<void>` — writes to WebContainer VFS via `webcontainer.fs.writeFile(path, newCode)`.
  - `rejectPatch({ workspaceId, path }): Promise<void>` — no-op; just closes the diff.
  - `undoLastPatch(workspaceId): Promise<void>` — reads the previous content from the workspace's snapshot history (store the last 5 versions per file in Dexie).
- Install `diff@^7.0.0` for the unified diff library.

### Task 1.5.2 — Create `src/components/os/panels/PatchApplier.tsx`

- `'use client'`. Props: `{ workspaceId, path, currentCode, fixedCode, onClose }`.
- Renders a modal (or full-width overlay) with a Monaco `DiffEditor`:
  ```tsx
  <DiffEditor original={currentCode} modified={fixedCode} language={lang} theme="vs-dark" />
  ```
- Buttons:
  - `Aceitar` → calls `applyPatch`, then `onClose`, then triggers a "file changed" event so the file tree updates.
  - `Rejeitar` → calls `onClose` without applying.
  - `Aplicar Manualmente` → opens the modified side in the regular editor for line-by-line editing; user can save when ready.
- After accept: show a toast "Patch aplicado a {path}."

### Task 1.5.3 — Wire the Save button to WebContainer

- In `CodeEditorApp.tsx`, change the Save button handler:
  ```typescript
  const handleSave = async () => {
    if (!activeWorkspaceId || !activeFile) return;
    await webcontainer.fs.writeFile(activeFile.path, activeFile.content);
    setDirty(false);
    addToGitIndex(activeWorkspaceId, activeFile.path);  // see Task 1.5.5
  };
  ```
- Show a small spinner on the Save button while writing.
- The file tree in `FileTreePanel` listens for a "fs change" event and re-reads the directory.

### Task 1.5.4 — Create `src/lib/runtime/vitestRunner.ts`

- Functions:
  - `ensureVitest(workspaceId): Promise<void>` — checks if `node_modules/vitest` exists; if not, spawns `npm install --no-save vitest` in the WebContainer and streams progress to the UI.
  - `runTests(workspaceId, specPath): Promise<VitestRunResult>` — spawns `npx vitest run --reporter=json {specPath}` in the WebContainer. Collects stdout, parses JSON, returns:
    ```typescript
    type VitestRunResult = {
      numPassed: number;
      numFailed: number;
      numTotal: number;
      tests: { name: string; status: 'pass' | 'fail'; message?: string }[];
      durationMs: number;
      rawOutput: string;
    };
    ```
  - `streamTests(workspaceId, specPath, onEvent): Promise<VitestRunResult>` — same as above but emits events (`onStdout`, `onTestPass`, `onTestFail`) for real-time UI updates.
- Vitest install progress: `webcontainer.on('install-packages', (data) => ...)` — convert to UI events.

### Task 1.5.5 — Create `src/lib/runtime/git.ts`

- Functions:
  - `initRepo(workspaceId): Promise<void>` — `webcontainer.spawn('git', ['init'])`. Called automatically on workspace creation.
  - `addFile(workspaceId, path): Promise<void>` — `webcontainer.spawn('git', ['add', path])`. Called on save.
  - `commit(workspaceId, message, author): Promise<{ sha: string }>` — `webcontainer.spawn('git', ['commit', '-m', message, '--author', author])`. Returns the commit SHA by parsing stdout.
  - `status(workspaceId): Promise<{ clean: boolean, changes: string[] }>` — `webcontainer.spawn('git', ['status', '--porcelain'])`, parse the porcelain output.
  - `log(workspaceId, limit = 20): Promise<{ sha: string; message: string; author: string; date: string }[]>` — `git log --pretty=format:'%H|%s|%an|%ad' --date=iso -n {limit}`.
- Add a `useGitStore` Zustand that polls `status` every 5s when a workspace is active and the file tree is open.

### Task 1.5.6 — Enhance `SwarmPanel.tsx` with `Auto-Patch` and `Gerar Testes`

- `Auto-Patch` button:
  - If the current audit has at least one finding with `fixedCode`, open `PatchApplier` with that fix.
  - If multiple, show a list to pick from.
- `Gerar Testes` button:
  - Reads the active file.
  - Calls `llmAudit` (existing) to get a structured understanding.
  - Calls the LLM again with a system prompt that instructs "respond with a Vitest spec for the following code"; parses the response.
  - Writes the spec to `{fileDir}/__tests__/{basename}.spec.ts` via `webcontainer.fs.writeFile`.
  - Calls `runTests(workspaceId, specPath)` and streams results to the panel.
  - On pass: green cards.
  - On fail: red cards with the failure message; offers "Pedir correção ao AnjosDebugger" (which feeds the failure back to the LLM for a fix).

### Task 1.5.7 — Add a "Commit" UI

- In the editor's status bar, show: branch name (default `main`), dirty count from `git status`, a `Commit` button.
- Clicking Commit opens a small modal: message input + author (from `APP_CONFIG` for v1, GitHub user in Phase 3).
- On submit: `git.commit(workspaceId, message, author)`; show toast with the SHA.

- `src/lib/runtime/git.test.ts`:

## Verification

- `pnpm tsc --noEmit` → 0 errors.
- `pnpm vitest run src/lib/runtime/` → all green.
- Manual E2E:
  1. Create a workspace, open Code Editor.
  2. Type `function add(a, b) { eval('return a+b'); }` in a new file `src/add.ts`.
  3. Save. `git status` in the terminal shows `?? src/add.ts`.
  4. Click `Auditar` — see findings (eval, plus more from LLM).
  5. Click `Auto-Patch` on the `eval` finding — diff editor opens with `return a + b`.
  6. Click `Aceitar` — file is updated. `git status` shows `M src/add.ts`.
  7. Click `Gerar Testes` — a spec is generated, `npx vitest run` is spawned, output streams to the panel. Test passes.
  8. Click `Commit`, type "fix: replace eval with return", commit. `git log` shows the commit.

## Out of scope (deferred)

- **Branch management** (checkout, merge, rebase): v1 only works on `main`.
- **GitHub push (RUN-04):** needs OAuth from Phase 3. Plan 1.5 sets up the local git workflow; Phase 3 adds the push.
- **Multi-file patches:** a single finding applies to a single file for v1.
- **Test debugging:** no breakpoints / step-through. Just run + see results.

## Risks

- **WebContainer `npm install vitest` can take 10-15s on first run.** Show a clear progress overlay with the install steps.
- **Vitest version drift:** pin to `vitest@^2.0.0` in the generated spec to avoid surprises.
- **`webcontainer.spawn('git', ...)` requires the WebContainer to mount a `node_modules/git` snapshot.** WebContainer has a known issue here; if it fails, fall back to running git via `jsh` as a child process.
- **Long-running test suites:** if `npx vitest run` doesn't exit (e.g., watch mode accidentally enabled), we have a hanging process. Always pass `--run` and `--reporter=json` to prevent this.
