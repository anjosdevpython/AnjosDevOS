# Plan 01-02 — WebContainers Runtime

## Goal

Add a **real Node + npm + git runtime** to the AnjosDevOS via `@webcontainer/api`, and wire a **functional xterm.js terminal panel** to it. This is the foundation that turns AnjosDevOS from a "fake OS" into a "real self-contained IDE".

## Context

- **What exists today:** `src/components/os/apps/TerminalApp.tsx` (202 lines) is a UI-only mock. Commands like `git status` return hardcoded strings. There is no process execution.
- **What this plan delivers:**
  1. The COOP/COEP headers required by WebContainers.
  2. A `webcontainer.ts` singleton that boots a WebContainer on first use and reuses it across workspaces.
  3. A reusable `<Terminal />` component based on xterm.js.
  4. A fallback "Demo Mode" for browsers that can't boot WebContainers.
  5. Refactor `TerminalApp.tsx` to mount the real terminal.
- **Why now:** Plan 1.3's IDE layout mounts the terminal in a panel; Plan 1.5's test runner and auto-patch both write to the WebContainer VFS. Nothing else makes sense without it.

## Tasks

### Task 1.2.1 — Install runtime dependencies

- `pnpm add @webcontainer/api@^1.6.1 @xterm/xterm@^5.5.0 @xterm/addon-fit@^0.10.0`
- `pnpm add -D @types/node` (already present, but ensure version ≥ 20 for WebContainer types).
- Commit: `chore(deps): add @webcontainer/api and xterm.js`.

### Task 1.2.2 — Add COOP/COEP headers in `next.config.ts`

- Edit `next.config.ts` to add a `headers()` async function:
  ```typescript
  async headers() {
    return [{
      source: '/:path*',
      headers: [
        { key: 'Cross-Origin-Opener-Policy', value: 'same-origin' },
        { key: 'Cross-Origin-Embedder-Policy', value: 'require-corp' },
        { key: 'Cross-Origin-Resource-Policy', value: 'same-origin' },
      ],
    }];
  }
  ```
- Note: the existing `next.config.ts` has `output: 'standalone'` and `images.remotePatterns`. Preserve both.
- Add a comment in the file explaining why COOP/COEP is required (WebContainers / SharedArrayBuffer).
- Commit: `feat(runtime): add COOP/COEP headers for WebContainers`.

### Task 1.2.3 — Create `src/lib/runtime/webcontainer.ts` singleton

- Module-scope singleton: `let instance: WebContainer | null = null;`
- Exported `getWebContainer(): Promise<WebContainer>`:
  - If `instance` exists, return it.
  - Else, call `WebContainer.boot()` and cache the result.
  - If boot throws (e.g., iOS Safari without COOP/COEP), set a module-level `isSupported = false` flag and throw a typed `WebContainerNotSupportedError`.
- Exported `isWebContainerSupported(): boolean` (returns the cached flag).
- Exported `tearDownWebContainer()` (for tests, also frees the ~150MB the runtime uses).
- Add a Zustand store `useRuntimeStore.ts` exposing `{ status: 'idle' | 'booting' | 'ready' | 'error', error: string | null, isSupported: boolean }` so the UI can show spinners.

### Task 1.2.4 — Add filesystem snapshot/restore for workspaces

- In `src/lib/runtime/webcontainer-fs.ts`:
  - `snapshotWorkspace(workspaceId)`: serializes the current VFS (excluding `node_modules`) to a JSON blob, stores in Dexie (new table `workspaceSnapshots` with `id (=workspaceId), data, updatedAt`).
  - `restoreWorkspace(workspaceId)`: reads the snapshot, mounts it as files in the booted WebContainer.
- Add `node_modules` to a separate Dexie table `workspaceNodeModules` (keyed by `workspaceId`) — WebContainer's built-in snapshot is heavy and we want a fast restore path.
- Update Dexie schema in Plan 1.1 to add these tables (or do a `version(2).stores(...)` migration if Plan 1.1 already shipped).

### Task 1.2.5 — Create `src/components/os/panels/Terminal.tsx`

- `'use client'`. Imports: `Terminal as XTerm } from '@xterm/xterm';`, `FitAddon } from '@xterm/addon-fit';`, `@xterm/xterm/css/xterm.css` (import in a wrapper or via `import 'xterm/css/xterm.css'` at top of file).
- Props: `{ workspaceId: string, height?: number }`.
- On mount:
  - Initialize `xterm = new XTerm({ theme: cyberpunk-dark, fontFamily: 'JetBrains Mono', fontSize: 13, cursorBlink: true })`.
  - Mount into a `div ref={terminalRef}`.
  - `fitAddon = new FitAddon(); xterm.loadAddon(fitAddon); fitAddon.fit();`
- On `xterm.onData(data => ...)`:
  - Push `data` to a local line buffer until a newline is received.
  - On newline, `webcontainer.spawn('jsh', ['-c', line])` (or use WebContainer's `spawn` with stdin piping).
  - Pipe `process.output` to `xterm.write()`.
  - On `process.exit`, write `\n$ ` prompt.
- If `isWebContainerSupported() === false`, render a "Demo Mode" view that prints mock responses (preserves the UX for iOS Safari / Firefox without COOP).
- Cleanup on unmount: `xterm.dispose()`.

### Task 1.2.6 — Refactor `src/components/os/apps/TerminalApp.tsx`

- Replace the mock with a mount of `<Terminal workspaceId={...} />`.
- Keep the title bar / window chrome (already in `Window.tsx`).
- Read the active workspace from `useWorkspacesStore`.
- Keep the NEOFETCH banner as a one-time welcome message written to xterm on first mount (via `xterm.writeln`).

### Task 1.2.7 — Wire legacy mock commands to real data

- Inside the xterm `onData` handler, intercept commands before passing to WebContainer:
  - `agents` → fetch from `getSwarmEngine().getAllAgents()` and print a table of {name, role, status}.
  - `swarm <goal>` → call `getSwarmEngine().executeCollaborativeCodingTask(goal, '', '')` and stream messages.
  - `audit <file>` → call `llmAudit(...)` (from Plan 1.4) — for now, stub.
  - `flows` → read from `flowRepository` (added in Phase 2).
  - `models` → read from `PROVIDERS` registry.
  - `neofetch` → print the existing NEOFETCH.
  - Anything else → pass to WebContainer.
- This preserves the existing UX while making the commands return real data.

### Task 1.2.8 — Capability detection + Demo Mode fallback

- On the `WorkspacesApp` and the `Terminal` component, call `isWebContainerSupported()` early.
- If false, show a banner: "WebContainers não disponível neste navegador. Demo Mode ativo — você pode usar o editor e o swarm, mas `npm install` e `git` não funcionam."
- In Demo Mode, the terminal still works but commands return friendly stubs.

## Out of scope (deferred)

- **Node process pooling** (one per workspace): single WebContainer shared, VFS swapped per workspace. Tearing down + rebooting is acceptable for v1 (~2-3s on workspace switch).
- **WebContainer preboot** in service worker: not needed in v1.
- **Custom xterm theme:** cyberpunk-dark is a reasonable default; can iterate later.

## Risks

- **WebContainer licensing** at scale: StackBlitz free tier covers dev. Production scale needs discussion.
- **COOP/COEP breaks cross-origin iframes**: acceptable for v1 (no third-party iframes).
- **First boot latency** on slow devices: 2-5s. Show a clear "Bootando ambiente..." overlay.
- **Process kill:** if a user spawns an infinite loop (`while(true)`), there's no way to kill it from xterm without a separate kill command. Add `Ctrl+C` mapping to `process.kill()`.
