# Plan 01-01 — Workspaces

## Goal

Build the **Workspaces** feature: users can create, list, open, rename, duplicate, and delete isolated project workspaces inside AnjosDevOS. Each workspace has its own VFS-backed project, editor session, terminal history, and Swarm runs — all persisted in IndexedDB via Dexie.

## Context

- **What exists today:** `src/components/os/apps/FileExplorerApp.tsx` (806 linhas) has a hand-rolled `FileNode` interface and a VFS that lives only in React state. No persistence; refresh = empty. No multi-workspace concept.
- **What this plan delivers:** persistent multi-workspace support, a Workspaces app visible in the OS, a repository pattern that hides Dexie details, and a Zustand store for the active workspace state.
- **Why now:** Phase 1.2 needs an active workspace to boot a WebContainer against. Phase 1.5 needs the session snapshot to restore cursor positions on reload. Nothing else makes sense without Workspaces.

## Tasks

### Task 1.1.1 — Install Dexie and add `package.json` entries

- `pnpm add dexie@^4.0.10` (latest stable).
- `pnpm add -D @types/dexie` if any types are missing (Dexie ships its own types in v4).
- Commit: `chore(deps): add dexie`.

### Task 1.1.2 — Create `src/lib/workspaces/db.ts` (Dexie schema)

- Define `AnjosDevOSDB` class extending `Dexie` with tables: `workspaces`, `sessions`, `swarmRuns`.
- Schema version 1:
  ```typescript
  this.version(1).stores({
    workspaces: 'id, name, createdAt, updatedAt, lastOpenedAt',
    sessions: 'id, workspaceId, updatedAt',
    swarmRuns: 'id, workspaceId, startedAt',
  });
  ```
- Export `db = new AnjosDevOSDB()` as a singleton.
- Define TypeScript interfaces `Workspace`, `EditorSession`, `SwarmRun` in `db.ts` (or a sibling `types.ts` if they get long).
- Add `src/lib/workspaces/index.ts` re-exporting `db`, `Workspace`, `EditorSession`.

### Task 1.1.3 — Create `src/lib/workspaces/workspaceRepository.ts`

- CRUD functions: `listWorkspaces()`, `getWorkspace(id)`, `createWorkspace({ name })`, `updateWorkspace(id, partial)`, `deleteWorkspace(id)`, `duplicateWorkspace(id)`, `touchLastOpened(id)`.
- All return `Promise<...>`; wrap Dexie calls in try/catch and re-throw as a typed `WorkspaceError` (extends `Error`).
- Hook helpers for sessions: `getSession(workspaceId)`, `saveSession(session)`, `clearSession(workspaceId)`.

### Task 1.1.4 — Create `src/lib/workspaces/store.ts` (Zustand)

- State: `activeWorkspaceId: string | null`, `activeWorkspace: Workspace | null`, `isLoading: boolean`, `error: string | null`.
- Actions: `setActiveWorkspace(id)`, `refreshWorkspaces()`, `createWorkspace(name)`, `deleteWorkspace(id)`, `renameWorkspace(id, name)`, `duplicateWorkspace(id)`.
- On `setActiveWorkspace(id)`: also `touchLastOpened(id)` in the repo, and persist `activeWorkspaceId` in `localStorage` key `anjosdev_active_workspace`.
- On boot (`useEffect`): read `anjosdev_active_workspace` from localStorage, fetch from Dexie, set as active.
- Add the store import to `src/types/index.ts` for central re-exports if needed.

### Task 1.1.5 — Create `src/components/os/apps/WorkspacesApp.tsx`

- Renders a list of workspaces with: name, last opened (formatted "há 2h"), a row of buttons (Abrir, Renomear, Duplicar, Deletar).
- Header bar with `+ Novo Workspace` button that opens a modal/prompt for the name.
- Clicking "Abrir" calls `setActiveWorkspace(id)` and then calls `openApp('codeeditor')` (assuming the code editor knows how to read the active workspace).
- "Deletar" shows a confirmation modal; on confirm, deletes from Dexie.
- Use the existing `Window` wrapper from `src/components/os/Window.tsx` for the title bar.
- Style with Tailwind tokens (cyber-card, neon-green accents, glass effect).

### Task 1.1.6 — Register Workspaces in `AppRegistry.tsx` + `types.ts`

- Add a new entry to `APP_DEFINITIONS` in `src/components/os/types.ts`:
  ```typescript
  { id: 'workspaces', title: 'Workspaces', iconName: 'Briefcase', color: 'neon-cyan', defaultWidth: 900, defaultHeight: 600, minWidth: 600, minHeight: 400, desktopIcon: true, category: 'tools' }
  ```
- In `AppRegistry.tsx`:
  - Add `Briefcase` to the `lucide-react` import.
  - Add `Briefcase: <Briefcase className="w-4 h-4" />` to `ICON_COMPONENTS`.
  - Add a lazy import: `const WorkspacesApp = dynamic(() => import('./apps/WorkspacesApp').then(m => ({ default: m.WorkspacesApp })), { ssr: false });`
  - Add a `case 'workspaces':` in `getAppContent` returning `wrapInBoundary(<WorkspacesApp />, 'Workspaces')`.

### Task 1.1.7 — Persistence: active workspace + session restore

- On `setActiveWorkspace(id)`, store `id` in `localStorage.anjosdev_active_workspace`.
- On app boot, the Zustand store reads this key, fetches the workspace from Dexie, and sets it active.
- For session restore: provide a `restoreSession(workspaceId)` function in `workspaceRepository.ts` that returns `EditorSession` (or `null`).
- Defer the "editor tabs restore" UI to Plan 1.3 (which builds the editor); this plan just ensures the data layer is ready.

## Risks

- **Dexie schema migrations** if we change fields in v2: handled by `version(2).stores({...}).upgrade(tx => ...)`. Document in `db.ts` JSDoc.
- **Multi-tab races:** single-tab assumption for v1. If a user opens two tabs, the last write wins. Document in `AGENTS.md`.
